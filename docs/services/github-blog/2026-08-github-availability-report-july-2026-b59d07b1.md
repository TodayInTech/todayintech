# GitHub availability report: July 2026

> GitHub Blog · 2026-08-12 · Company news / Reliability

---

7월 GitHub 가용성 보고서는 한 달 동안 발생한 여덟 건의 주요 사고와 그 대응을 통해 '가용성 우선' 원칙으로의 변화와 인프라 아키텍처 전환 진행 상황을 상세히 보여준다. 보고서는 특히 GitHub Actions 관련 장기간 장애(본문에서 8월 6일 사건도 언급)를 계기로 Actions의 아키텍처 로드맵을 가속화하고 Azure로의 이전을 통해 더 큰 수용력과 격리 능력을 확보하려는 전략을 강조한다. 실제로 7월 한 달 동안 모놀리식 읽기 트래픽이 Azure Central US에서 최대 52.75%를 기록했고 Git 트래픽은 47%로 증가했으며, 저장소의 29%가 중앙 리전에 복제본을 확보하게 되어 장애 시 페일오버 충격을 줄이는 진전이 있었다고 보고했다. 또한 인증·권한 조회 등 핵심 경로를 전용 서비스로 분리해 피크 쿼리를 오프로드하고, 아티팩트 테이블 쿼리 시간 절반 단축, 인증 경로 캐시로 18.2% 부하 감소 등 구체적 성과를 제시한다.
개별 사건별로는 자동 인프라 메타데이터 업데이트의 불변성 부족이 서비스 디스커버리를 망가뜨려 수시간 복구를 초래한 DNS·메타데이터 사고, GitHub Actions의 호스트 러너 프로비저닝 백엔드 복제 불안정으로 인한 작업 지연, 외부 검색 제공자 장애, 내부 DNS 재구성 오류, 인증서 수명 주기 관리 실패로 인한 러너 연결 단절, SSH 공개키 인증 플로우 회귀, Vitess 키스페이스 백필 취소로 인한 PR 생성 오류, Redis 클러스터 확장 과정의 지역 불균형으로 인한 Actions 지연 등 원인과 복구 조치(메타데이터 불변성 강화, 모니터링·롤아웃 개선, 인증서 자동화, DNS 제어 평면 안전장치, 사전 검증과 용량 검사 강화 등)를 항목별로 기술하고 있다. 보고서는 50% 돌파를 중간 지점으로 규정하고 중앙 리전으로의 트래픽 이전을 올해 말까지 진행해 지역 손실을 견딜 수 있는 수준의 독립적 Azure 용량 확보를 다음 목표로 제시하며, 인프라 분리·자동화·관측성 개선이 향후 유사 사고의 발생 가능성과 영향을 줄이는 핵심 수단임을 밝힌다.
