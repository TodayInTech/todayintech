# How to evaluate LLMs before production

> GitHub Blog · 2026-08-25 · AI &amp; ML / LLMs

---

저자는 GitHub의 시크릿 스캐닝에서 발견한 실무 교훈을 바탕으로, LLM 기반 시스템을 프로덕션에 옮기기 전 평가를 제품 결정 관점에서 설계하라고 권합니다. 단순히 모델 성능(벤치마크 점수)만 보는 대신 ‘무엇을 결정하려는가’를 먼저 정하고, 주요 성과지표(거짓양성 감소·정밀도)를 주목하되 안전 제약(재현율)은 감수할 수 없는 가드레일로 둡니다. 또한 평가 기준을 1) 사용자 성과(거짓양성 감소), 2) 안전 제약(재현율), 3) 운영적 가드레일(지연·비용·신뢰성·통합성)로 나누어 서로 교환 가능한 지표로 혼동하지 않도록 한 점이 핵심입니다.
오프라인 평가는 통합 테스트처럼 반복·버전관리하고, 의미 있는 변경 때마다 재실행해야 하며 한 번에 하나의 주요 변수를 바꿔 원인을 명확히 해야 한다고 강조합니다. 실제 프로덕션과 유사한 입력 형식·문맥을 유지하지 않으면 오프라인 점수가 과대평가될 수 있고, 프로덕션 레이블은 워크플로우 결과를 반영할 뿐 진실을 항상 나타내지는 않으므로 수작업 검토가 필요하다고 경고합니다. 합성·오픈 데이터는 커버리지 보완에 유용하고, 오류 분석을 통해 모델·프롬프트·입력·데이터 라벨 중 어느 부분을 고쳐야 할지 구체화할 수 있습니다. 저자들은 LLM을 판사로 활용해 사람 검토를 우선순위화할 것을 제안하며, 이러한 과정을 통해 오프라인 데이터셋에서 거짓양성을 95% 줄이면서 재현율 가드레일을 지켰다고 보고합니다. 전반적으로 이 글은 LLM 시스템의 실제 배포 위험을 가시화하고, 통제된 온라인 실험으로 안전하게 이행하기 위한 실무적 체크리스트를 제공합니다.
