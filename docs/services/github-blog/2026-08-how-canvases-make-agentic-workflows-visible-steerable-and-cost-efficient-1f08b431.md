# How canvases make agentic workflows visible, steerable, and cost-efficient

> GitHub Blog · 2026-08-17 · GitHub Copilot

---

대화형 인터페이스는 의도를 전달하는 데 강하지만, 실제 에이전트가 실행한 작업과 의사결정 이력을 추적하기에는 한계가 있다는 관찰에서 글이 출발한다. GitHub Copilot 앱의 '캔버스'는 작업을 지속적이고 가시적인 표면 위에 올려 에이전트와 인간이 같은 상태를 보며 조정할 수 있게 한다. 작성자는 Java Modernization Studio와 Site Studio 같은 캔버스를 직접 만들어 각 단계의 상태, 중요한 결정 지점, 임시 초안, 사람이 승인해야 할 지점 등을 명시적으로 드러내는 방식으로 채팅-스크롤에서 발생하는 맥락 손실과 과도한 검토 비용을 줄였다고 설명한다. 반복되는 워크플로우를 캔버스로 구조화하면 프롬프트 기반 상호작용을 넘어서 메모리와 제어를 갖춘 시스템으로 전환된다는 주장이 핵심이다.
기술적·비용적 실무 고려도 함께 제시된다. 글쓴이는 Site Studio에 약 2,000 AI 크레딧, 현대화 캔버스에 약 3,000 AI 크레딧이 들었다고 밝히며 초기 설계와 운영은 투자이지만 반복적 작업에서 프롬프트 반복과 문맥 재구성, 재작업을 줄여 장기적으로 시간과 비용을 절감한다고 평가한다. 실제 사용 권고로는 한 가지 반복 워크플로우를 골라 /create-canvas로 최소한의 캔버스를 만들고 실무로 돌려가며 개선하라고 조언한다. 작성자 Ayan Gupta는 GitHub의 Developer Advocate로, 글은 에이전트 중심 협업을 투명하고 제어 가능하게 만드는 캔버스의 실용적 설계 지침과 의미를 실무자 관점에서 전한다.
