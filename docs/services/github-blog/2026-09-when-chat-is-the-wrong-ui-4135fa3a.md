# When chat is the wrong UI

> GitHub Blog · 2026-09-24 · AI &amp; ML

---

LLM과의 상호작용이 등장한 이후 여전히 기본 인터페이스는 대화형 채팅박스다. 저자는 채팅이 보편성을 제공한 이유는 인정하면서도, 사용자가 해결하려는 구체적 작업 관점에서는 채팅이 오히려 비효율적일 수 있다고 지적한다. GitHub Copilot 앱에서 제안하는 대안은 ‘캔버스’라는 개념이다. 캔버스는 브라우저 크롬 없이 앱 내에서 동작하는 작은 풀스택 애플리케이션으로, 서버 구성요소와 에이전트가 양방향으로 통신한다. 글은 캔버스의 동작 원리와 장점을 예시로 풀어 보여준다: 에이전트와 함께 놀 수 있는 Connect 4 게임, 윈도우 패키지 매니저(Winget)를 위한 UI, 로컬 코드 실행과 서드파티 API 호출이 가능한 SQLite 캔버스 등은 단순한 채팅보다 더 직접적이고 반복 가능한 작업 흐름을 제공한다.
기술적 의미는 명확하다. 캔버스는 한 번 구축해 두면 이후 상호작용을 비용(토큰)과 주의력 측면에서 절감시키는 도구가 될 수 있으며, 인텔리센스 같은 편의 기능을 통합해 개발자 경험을 개선한다. 저자는 에이전트가 조사·프로토타입을 만들고 검토를 요청하도록 하여 인간을 가능한 한 루프에서 빼내는 것이 목표라고 설명한다. 다만 모든 캔버스가 즉시 완성되는 것은 아니며, 워크플로우용 캔버스는 설계와 자동화에 시간이 들 수 있음을 경험적으로 언급한다. 제공된 사례들은 채팅 기반 상호작용을 보완하는 보다 구조화된 인터페이스가 실제 개발 작업에서 실질적 이익을 줄 수 있음을 보여준다.
