# Git security vulnerabilities announced

> GitHub Blog · 2026-11-10 · 보안

---

Git 프로젝트가 **6건의 보안 취약점**을 수정한 새 릴리스를 공개했습니다. 수정은 **Git 2.56.1**에 포함되며, 2.55.1, 2.54.1, 2.53.1, 2.52.1, 2.51.3, 2.50.2에 대한 백포트도 제공됩니다. GitHub는 github.com과 GitHub Enterprise Cloud 등 플랫폼에 패치를 배포했고, GitHub Enterprise Server용 업데이트(3.19.15, 3.20.11, 3.21.9, 3.22.4)도 공개했습니다. 배포판 또는 애플리케이션에 번들된 Git을 포함해 가능한 한 빨리 업그레이드할 것을 권장합니다.

## CVE-2026-111760: 재귀적 클론 중 임의 코드 실행
인덱스 처리에서의 정수 절단(truncation)으로 인해 매우 긴 경로가 검증을 통과한 뒤 짧은 이름으로 기록될 수 있는 불일치가 발생했습니다. 공격자는 이를 이용해 서브모듈의 .git 파일을 심볼릭 링크로 바꾸고, 이후 재귀적 복제(recursive clone) 과정에서 원격이 제공한 디렉터리를 통해 임의 코드를 실행할 수 있습니다. 수정은 길이가 극단적으로 긴 인덱스 항목 경로를 사전에 거부하도록 변경하는 방식입니다.

## CVE-2026-113408: 서버가 광고한 HEAD를 통한 경로 횡단
프로토콜 v2로 빈 저장소를 복제할 때 서버가 ‘unborn branch’로 향하는 symref(HEAD)를 광고할 수 있는데, Git이 그 대상 이름을 검증하지 않고 로컬에 저장하면서 발생했습니다. 악의적 서버가 경로 횡단 문자열을 전달하면 files reference backend 사용 시 이후 참조 업데이트가 의도한 디렉터리 밖에 쓰기를 발생시킬 수 있습니다. 릴리스는 프로토콜 v2로 수신한 심볼릭-레퍼런스 대상과 다른 참조 이름들을 검증하도록 변경했습니다.

## CVE-2026-114467: 서명 제거 시 스택 손상
GPG 서명 스트립 코드가 최대 두 개의 서명만 있다고 가정하면서 고정 크기 스택 배열을 사용했고, 세 개 이상 서명이 있는 특수한 메시지는 배열 끝을 넘겨쓰게 되어 메모리 손상(및 서비스 거부)을 초래할 수 있었습니다. 수정은 고정 크기 배열을 제거하고 임의 수의 서명을 안전하게 처리하도록 변경했습니다.

## CVE-2026-114469: 바이너리 패치 처리 중 범위 밖 읽기
패치 입력 자체 크기만 검사하던 로직은 압축·인코딩으로 인해 실제 확장된 크기가 1GiB 제한을 초과할 수 있는 바이너리 패치를 충분히 검증하지 못했습니다. 악의적 패치는 입력 크기 검사를 우회해 범위 밖 읽기를 유발할 수 있습니다. 해결책은 처리 전에 선언된 비압축 크기도 검사하도록 추가한 것입니다.

## CVE-2026-105437: 대형 병합 중 힙 손상
병합 결과 크기를 계산할 때 오버플로가 발생하면 너무 작게 할당된 버퍼에 쓰기가 이루어져 힙 손상이 생길 수 있습니다(특히 많은 충돌과 큰 conflict-marker-size 속성이 결합된 경우). 이 문제는 호스팅 서비스가 사용자 대신 병합을 수행할 때도 영향을 미칩니다. 수정은 크기 적합 타입과 체크된 산술을 사용하고, 표현할 수 없을 만큼 큰 출력 크기는 거부하도록 변경했습니다.

## CVE-2026-114466: fast-import 스트림을 통한 파일 시스템 접근
git fast-import의 일부 기능(rewrite-submodules-from, rewrite-submodules-to, export-pack-edges)이 신뢰되지 않은 입력 스트림에 대해 파일을 읽거나 생성/덧붙일 수 있었고, 관련 명령은 이제 입력 스트림을 통한 경우 거부됩니다. 필요한 경우 호출자가 명시적으로 --allow-unsafe-features를 사용해 허용해야 하며, 이 옵션은 스트림을 생성한 프로그램을 신뢰할 때만 사용해야 합니다.

추가 하드닝으로 체크아웃과 트리 처리 중 인덱스 항목 할당에 대한 오버플로 검사도 도입되어, 경로 길이 제한과 함께 경로를 메모리로 복사하기 전에 할당 크기가 절단되거나 오버플로되는 것을 방지합니다.

영향 범위와 실무적 조치: Git 로컬 클라이언트뿐 아니라 애플리케이션(예: GitHub Desktop, GitHub Copilot 앱)과 자동화·호스팅 환경이 영향을 받습니다. 근거 문서는 가능한 한 빨리 **Git 2.56.1** 또는 해당 유지보수 시리즈의 패치 릴리스를 설치하고, Git을 번들로 포함하는 애플리케이션도 업데이트하라고 권고합니다. 즉시 업데이트가 불가능할 경우에는 피드의 지침대로 신뢰할 수 있는 서버에서만 복제하고(특히 재귀적 클론 회피), 신뢰하지 않는 저장소의 병합·태그 처리·바이너리 패치·fast-import 스트림은 피해야 한다고 명시되어 있습니다.

근거: GitHub 블로그의 공개 고지(Elijah Newren 작성)와 릴리스 설명(문서 내 CVE별 수정 사항 및 권고)을 기반으로 정리했습니다.
