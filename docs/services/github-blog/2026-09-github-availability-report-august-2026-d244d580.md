# GitHub availability report: August 2026

> GitHub Blog · 2026-09-10 · Company news

---

8월 한 달간 GitHub는 다섯 건의 가용성 사고로 성능 저하를 경험했고, 회사는 이를 계기로 용량·회복성 개선 작업을 가속화하고 있다고 보고했습니다. 플랫폼 성장으로 읽기·Git 트래픽이 정점에 도달한 가운데(Azure로 마이그레이션된 서비스의 읽기 비중 60.4%, Git 읽기 54%), 오래된 공유 DB에서 약 100만 qps를 제거하고 추가로 120,000 qps를 줄이는 쿼리 정리 작업을 수행해 시간당 약 59,000초의 불필요한 DB 작업을 제거했다고 밝혔습니다. Actions 쪽에서는 작업 라우팅을 통해 제약된 클러스터에서 예비 용량으로 33%의 잡을 이동시켜 캐시 CPU 피크를 98%에서 80%로 낮추는 등 단기 완충을 마련했고, Git 과부하 보호와 엣지 레벨의 로드셰딩으로 더 많은 트래픽(6.4%)을 처리하면서 지연의 95번째 백분위가 24% 개선되는 성과를 냈습니다. 관측과 텔레메트리도 보강해 병합·리뷰·코멘트 실패를 개별 측정하고, 자동 고임팩트 탐지에 고객지원 신호를 결합하는 등 탐지·대응 역량을 높였습니다.
구체적 사고 사례를 보면 8월 6일에는 내부 Actions 서비스의 배포 중 파드 수 감소가 잔여 사이트의 용량 한계를 넘겨 사이드카 CPU 스로틀링과 OOM 재시작을 유발했고, 잡 할당 경로의 잠재적 버그가 회복을 지연시켜 장시간 장애로 이어졌습니다. 17일에는 특정 데이터센터의 로드밸런서·사이드카 동시성 한계와 클라이언트 재시도 증폭으로 인증 경로가 마비됐고, 20일에는 Copilot 클라우드 에이전트의 상태 저장 DB가 제공자 측 지역 장애를 겪어 처리 지연과 백로그가 발생했습니다. 26일과 27일 사고에서는 공유 인프라의 성장 대비 부족한 용량과 외부 모델 제공자의 장애가 각각 영향을 미쳤습니다. 대응으로는 Azure로의 추가 마이그레이션, DB 프라이머리 이동, 서비스메시·사이드카의 오토스케일·헤드룸 확보, 재시도·백오프 정책 개선, 자동 회복과 회선 차단(서킷브레이커) 도입, 관리형 DB 페일오버·런북 정비 등 단기·중장기 조치가 계획되어 있습니다. 전반적으로 월별 성장과 피크 부하가 공유 인프라의 한계를 드러냈고, GitHub는 격리(isolation), 용량확보, 관측성 개선을 우선순위로 두고 위험을 낮추려는 방향을 명확히 했습니다.
