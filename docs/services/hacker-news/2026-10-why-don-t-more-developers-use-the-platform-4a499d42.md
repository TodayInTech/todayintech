# Why don't more developers “use the platform”?

> Hacker News · 2026-10-04 · 웹 개발

---

웹 표준 옹호자들이 반복해온 권고인 '플랫폼을 사용하라'는 주장에 대해 저자는 반대 입장의 이해가 필요하다고 시작한다. 브라우저의 기능이 라이브러리보다 뒤처졌던 역사적 배경(IE6 등)과, React 같은 프레임워크 생태계에서 익숙한 관습이 개발자를 npm 패키지로 이끈다는 점을 핵심 이유로 든다. 문서화 측면에서도 MDN·web.dev가 자리를 잡기 이전에는 예제와 튜토리얼이 블로그나 StackOverflow, README 중심으로 흩어져 있어 플랫폼 API보다 잘 다듬어진 서드파티 패키지를 더 쉽게 소비하게 만들었다는 설명이 이어진다. 또한 모달 구현 예시처럼 직접 만들며 배우고 싶은 동기, 즉 'IKEA 효과'가 개발자들로 하여금 플랫폼 대신 자신만의 구현을 선택하게 하는 심리적 요인으로 작용한다고 짚는다.
다만 저자는 무조건 플랫폼을 배척하는 행위가 항상 정당화되는 것은 아니라고 본다. CSS의 난해함이나 플랫폼 내부 동작을 몰라 사용자 레벨에서 자의적 구현이 생긴 사례들을 들어(예: line clamping, textarea 크기 조정) 무지에서 비롯된 과잉 구현 문제를 경고한다. ClickHouse 사례처럼 플랫폼 문서를 읽고 벤치마크를 해보니 자체 솔루션보다 플랫폼에 맡기는 편이 더 효율적이었던 경험을 공유하며, AI 코딩 도구의 등장이 이 문제를 어떻게 바꿀지에 대해 낙관적·비관적 전망을 모두 제시한다. 요컨대 '플랫폼을 사용하라'는 만트라는 가치가 있지만, 플랫폼을 외면하게 만든 역사적·심리적 요인과 AI 도구의 양면성을 이해해야 실무적으로 더 나은 선택을 할 수 있다는 점이 기술적 시사점이다.
