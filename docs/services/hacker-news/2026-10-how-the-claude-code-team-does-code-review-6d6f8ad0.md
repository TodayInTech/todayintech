# How the Claude Code team does code review

> Hacker News · 2026-10-16 · 소프트웨어 엔지니어링

---

Anthropic의 Claude Code 팀은 에이전트가 코드의 대부분(약 90%)을 작성하는 상황과 하루 수천~수만 건의 변경에 대응하기 위해 '인간 시간을 최소화하면서 리버트와 사고를 늘리지 않는' 코드리뷰 흐름을 설계했다. 6~9월 사이 병합된 PR이 두 배 이상 늘어나는 동안 되돌린 비중은 40% 이상 줄었고, 리뷰는 끝단의 게이트가 아니라 글쓰기 중 작동하는 연속적 검증으로 바뀌었다. 팀은 에이전트에게 테스트·빌드·스크린샷 등으로 스스로 결과를 검증하게 하고, PR 전후로 여러 서브에이전트가 병렬로 버그를 찾고 수정하며, 발견물은 다른 에이전트들이 교차 검증해 합의가 나야 사람에게 올라가도록 해 노이즈를 줄이고 있다. 연구 프리뷰 도입 후 내부 PR에서 실질적 코멘트 비율이 16%에서 54%로 증가한 점은 자동 리뷰가 실제로 문제 지점을 더 잘 포착했음을 보여준다.
운영적 디테일도 구체적이다. 버그·보안 리뷰는 자동화되어 열려 있는 발견이 있으면 병합 불가이며, 변경 분량·영향을 판별하는 분류기가 리스크 티어를 정해 사람 승인 수를 달리한다. 승인권한은 신뢰된 작성자 목록으로 제한되며, 자동 검토는 사람 승인을 대체하지 못한다는 원칙을 유지한다. 또한 발견마다 수정하거나 스레드를 해명해야 하고, 머지 큐가 메인에 적용된 상태에서 모든 체크를 재실행해 두 PR이 합쳐져 문제를 만들지 않게 한다. 에이전트와 인간의 반복적 리뷰가 무한 루프가 되지 않도록 라운드 수와 리콜을 측정해 재검토 정책을 조정하고, 오래된 버그는 야간 에이전트가 찾아내는 방식으로 사후 보완한다. 결과적으로 인간의 역할은 모든 라인을 읽는 것에서 고차원적 판단과 시스템 이해(필요할 때 Claude에게 현재 코드 설명을 생성시키는 방식)로 이동했음을 보여주며, 팀은 사고 발생 시 어떤 층에서 놓쳤는지 평가해 자동화·문서·스킬로 보완하는 순환을 운영하고 있다.
