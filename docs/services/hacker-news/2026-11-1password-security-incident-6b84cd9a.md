# 1Password Security Incident

> Hacker News · 2026-11-25 · 보안 사고

---

2026년 11월 19일 발생한 사건을 1Password가 11월 25일 확인·보고했다. 공격자는 한 직원의 기업 GitHub 계정 접근을 통해 **사설 저장소의 소스코드 복사**와 CI/CD 시스템 접근을 확보했고, 이 과정에서 백엔드 서비스에 악성 코드를 밀어넣어 일부 고객의 관리형 계정 데이터를 다운로드했다고 회사는 밝혔다 (공식 블로그).

## GitHub 계정 침해와 CI/CD 접근
공격자는 침해된 GitHub 계정을 발판으로 소스코드를 가져가고 CI/CD에 접근해 인프라 관련 자격증명에 노출 가능성을 만들었다. 1Password는 영향을 받은 GitHub 계정 비활성화, 도난된 토큰 폐기, 공격자가 만든 접근 제거와 함께 **노출 가능성이 있는 내부 자격증명 전량 회전(rotate/revoke)** 조치를 취했다고 보고했다. 회사는 서비스 가용성, 제품 보안에 영향이 없다고 밝혔다.

## 노출된 정보 범위와 의미
공개된 내용에 따르면 공격자가 다운로드한 항목은 다음과 같다(회사 설명 그대로):
- 고객 이름과 이메일
- 계정·사용자 식별자, 생성 시각·마지막 로그인 시각
- 공개키(설계상 공개)
- Secure Remote Password(SRP) 프로토콜 파라미터(계정 접근에 사용 불가)
- 초대·프로비저닝·계정 복구 이메일 링크에 포함된 토큰
- 내부 아키텍처 관련 비밀이 아닌 메타데이터

중요한 점은 1Password가 반복해서 밝힌 대로 **사용자 금고(버추얼 금고) 내용, 계정 비밀번호, 시크릿 키(Secret Key), 계정 복구 키 등은 저장하지 않거나 노출되지 않아 암호화된 금고 내용 자체는 공격자가 접근할 수 없다는 점**이다. 다만 이름·이메일과 계정 메타데이터는 사회공학·피싱 공격에 활용될 수 있으므로 실무적으로 위험도가 상승한다.

## 토큰 처리 변경 — 브루트포스 저지
초대·프로비저닝·복구에 사용되는 이메일 토큰은 단독으로 계정 접근을 허용하지 않지만, 1Password는 추후 추측(guessing) 가능성을 낮추기 위해 기존 **숫자 6자리** 코드를 **영숫자 10자리**로 확장했다. 회사는 토큰만으로는 계정 접근이 불가능하며, 초대·복구는 SSO 로그인이나 이메일로 보낸 코드와 결합되어야 완료된다고 설명했다. 또한 내부 탐지 체계와 엔드포인트·CI/CD·GitHub 통제를 강화하고 새 탐지 규칙을 도입했다고 덧붙였다.

## 실무적 영향과 권고
- 기업 및 개인 사용자는 예기치 않은 1Password 관련 이메일·문자·전화에 주의해야 한다. 특히 초대·복구 절차를 가장한 피싱 시도가 늘어날 수 있다(1Password 권고).
- 1Password는 사용자 비밀번호나 시크릿 키를 요구하지 않으므로, 관련 정보 요구는 피싱 징후로 간주해야 한다.
- 서비스 측 대응으로 내부 자격증명 회전과 토큰 길이 확대가 시행됐으나, 사용자는 계정 복구 연락·초대 이메일을 받은 경우 발신자·링크 목적을 신중히 확인할 필요가 있다.

1Password는 독립 보안 전문가를 참여시켜 격리·복구 조치의 적절성을 검증했고, 추가 증거가 발견되면 블로그 포스트를 업데이트하겠다고 밝혔다. 본 보도는 1Password 공식 블로그 내용(chunk-0001, chunk-0002)을 근거로 작성했으며, 회사 발표 범위 밖의 추가 기술 세부사항은 공개되지 않았다.
