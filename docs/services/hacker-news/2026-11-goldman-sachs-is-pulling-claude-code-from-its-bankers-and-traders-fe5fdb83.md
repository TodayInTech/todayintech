# Goldman Sachs is pulling Claude Code from its bankers and traders

> Hacker News · 2026-11-08 · 금융·AI 정책

---

Goldman Sachs가 **Anthropic의 Claude Code와 Microsoft의 GitHub 기반 코딩 에이전트를 엔지니어로만 제한**하는 내부 지침을 10월에 업데이트했다. 이로써 트레이더와 은행업무 담당자들은 더 이상 해당 코딩 에이전트를 업무용으로 사용할 수 없게 됐으며, Strats(트레이딩·퀀·소프트웨어 교차 역할을 하는 인력)만 예외적으로 접근 권한을 유지한다(블룸버그 보도 인용).

## 직무 기반 접근 제한의 내용
제한은 위치가 아닌 **직무(역할)**를 근거로 한다. 앞서 4월에는 홍콩 소속 은행가들에게 Claude 접근을 막았는데, 그때는 계약·지역 문제에 따른 조치였다. 이번에는 엔지니어(약 12,000명)로 구성된 집단만 코딩 에이전트를 사용하도록 권한을 한정했다. 골드만의 내부 AI 어시스턴트(여러 모델 사용)는 여전히 전사적으로 사용 가능하지만, 스스로 코드 작성·실행이 가능한 서드파티 에이전트는 제한 대상이다.

## 왜 거래 데스크에서 문제인가
코딩 에이전트는 파일을 읽고 프로그램을 작성·실행하며, 일반 사용자 권한으로 움직인다. 엔지니어가 작성한 코드는 리뷰·테스트·배포 통제를 거치는 반면, 트레이더가 에이전트로 만든 스크립트는 그러한 절차 없이 일상 업무에 투입될 수 있다. 정보 장벽(정보 비공개 구역) 준수나 데이터 권한 관리, 코드의 예외처리·신뢰성 문제 등 규제·운영 리스크가 근거로 제시됐다. 또한 비용(토큰 기반 청구)과 생산성·지출 증가도 검토 요인으로 언급됐다.

## 실무적 파장과 남은 과제
영업·트레이딩 팀에서 에이전트로 빠르게 만든 도구들을 엔지니어가 수렴해 검토·정비하는 프로세스가 핵심적이다. 보도에 따르면 골드만은 Anthropic 엔지니어들과 협력해 후방업무용 Claude 기반 에이전트를 구축해 운영해왔고, Anthropic의 IPO(S-1 제출 10월26일, 티커 ANT)에서 골드만이 인수인 역할을 하고 있다는 점이 대조적이다. 은행 내부는 "최적 사용 사례를 판별하기 위해 일부 AI 도구를 직원에게 제공"한다고 대변인이 밝혔다.

보도·분석은 이번 조치가 거래 현장의 무심사 코드 실행 위험과 정보 장벽 문제에 대한 합리적 대응이라고 평가하면서도, 도입 후 철회 방식을 문제 삼았다. 실제로 트레이더들은 클라이언트 플로우 모니터링·포지션 모델링 등 실무적 용도로 해당 도구를 활용해 왔고, 이러한 사용 사례를 엔지니어링 팀이 수집해 제도화하는 작업이 필요하다고 지적된다.
