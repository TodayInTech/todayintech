# Omarchy: Any User Process Can Escalate to Root

> Hacker News · 2026-08-30 · 보안

---

Omarchy의 기본 설치가 개발자 편의를 위해 기본 사용자 계정을 docker 그룹에 포함시키는 설정을 사용하다 보니, 사용자 세션에서 실행되는 거의 모든 프로세스가 비밀번호·sudo·권한 프롬프트 없이 루트 권한으로 상승할 수 있는 취약점이 발생했습니다. 이유는 Docker 데몬이 루트로 동작하며 /var/run/docker.sock을 통해 소켓으로 통신하므로 docker 그룹에 속한 사용자는 데몬에 컨테이너를 루트로 띄워 호스트 파일시스템을 마운트하고 그 안에서 루트로 파일을 읽고 코드를 실행하도록 요청할 수 있기 때문입니다. 작성자는 /etc/shadow를 읽는 간단한 PoC를 제시하며 이 공격 경로를 입증했고, 문제는 책임감 있는 보고 절차를 통해 제출되어 4.0.1에서 패치되었습니다.
문제의 범위는 보조 그룹이 자식 프로세스에 상속된다는 점 때문에 단순하지 않습니다. systemd --user 아래의 거의 모든 정상 프로세스에 docker 그룹 권한이 있어 브라우저, 에디터·IDE, npm 스크립트, AI 에이전트 등 신뢰할 수 없는 코드가 실행될 수 있는 거의 모든 지점에서 즉시 전체 머신 권한 획득으로 이어질 수 있습니다. 또한 이 설정은 사용자가 선택하지 않아도 적용되는(옵트아웃) 기본값이었고 문서에는 “root로 실행하지 않음”으로 오해될 수 있는 설명이 있어 보안 의미가 충분히 고지되지 않았습니다. 영향 버전은 4.0.1 이전(작성자는 3.8.4에서 테스트)이며 커밋 타임라인(2025-06-01 도입, 2025-06-02 일시 비활성화, 2025-06-17 재활성화, 2026-08-24 기본 설정에서 제거)이 제공됩니다. 기술적 시사점으로는 개발자용 배포판에서의 보안 민감한 기본값의 중요성과 데몬리스인 Podman 같은 대안 도입 권고가 있으며, 신속한 패치 대응은 긍정적이나 배포판의 보안 의사결정 신뢰성에 대한 저자의 우려도 함께 제기되고 있습니다.
