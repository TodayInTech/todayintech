# Samsung's Processing-in-Memory (PIM)

> Hacker News · 2026-08-29 · 메모리·프로세서 통합(PIM)

---

삼성은 Hot Chips 2026에서 LPDDR5X-PIM을 통해 DRAM 내부에 MAC 유닛을 배치해 메모리 칩 내부 대역폭을 직접 활용하는 방안을 제시했다는 점이 핵심이다. 제시된 설계는 16개 뱅크마다 PIM 블록을 두어 칩 내부 대역폭 614GB/s를 활용하며, 일반 DRAM 접근의 병렬 한계(최대 76.8GB/s)와 대비된다. PIM 블록은 MAC 트리와 명령/소스/스케일 레지스터(1024비트 명령 레지스터로 64개 16비트 명령 보관, 4kbit 소스 레지스터, 2kbit 스케일 레지스터 등)를 포함하고, INT8·FP8·4비트 가중치 같은 저정밀 포맷을 지원해 패키지 단위로 2.4 TOPS(4비트 가중치 기준)에 이르는 처리량을 제시한다. 표준 LPDDR5X 프로토콜을 유지하면서도 특수 행 주소를 MMIO처럼 사용해 싱글-뱅크/멀티-뱅크 모드를 전환하고, PIM 레지스터 활성화 상태에서 읽기·쓰기 동작을 연산으로 재해석하는 방식으로 호환성을 확보한 점도 눈에 띈다.
하지만 문서가 지적하듯 실무 적용은 복잡하다. PIM 모드는 명령의 의미를 바꾸기 때문에 일반 메모리 액세스와 동시 사용이 불가능하고, 채널 단위로 PIM 전용 영역을 격리해야만 안전하게 쓸 수 있어 메모리 인터리빙과 대역폭 활용에 제약이 생긴다. 캐시·프리페치·추측 실행이 일으키는 부작용 때문에 PIM 영역을 비캐시화하고 비추측적 액세스로 다뤄야 하며, 이는 CPU/GPU 성능을 심각하게 저하시킬 수 있다. 운영체제 관점에서는 컨텍스트 전환·프리엠션 처리, PIM 상태 저장·복구 문제가 남아 있고, 저자는 이를 해결하려면 DRAM 인터페이스에 전용 연산 명령을 추가하거나 메모리 컨트롤러를 캐시 일관성의 동료로 동작하게 만들고, “rep macb” 같은 블록 MAC 명령을 도입하는 등 메모리 서브시스템 전반의 변경이 필요하다고 제안한다. 전통적 메모리·프로세서 소프트웨어 모델과의 마찰을 고려하면, 표준 컨트롤러 호환성은 있지만 실제 채택에는 하드웨어·OS·컴파일러 차원의 동시 개편이 선행되어야 한다는 결론이 도출된다.
