# Rendering huge pull requests in the GitHub Copilot app

> GitHub Blog · 2026-09-23 · Engineering

---

GitHub Copilot 앱의 풀 리퀘스트 뷰를 대규모 사례(2,200개 파일, 백만 행 이상, 400개 이상의 인라인 리뷰 코멘트)를 기준으로 다시 설계한 경험을 정리한 글입니다. 저자들은 코드 라인만 존재할 때의 전통적 가상화(모든 행 높이를 미리 알 수 있다는 계약)에 기반한 설계를 유지하되, 가변 높이의 리뷰 쓰레드·드래프트·리플라이 컴포저 등 ‘동적 블록’이 그 가정을 깨뜨린다고 지적합니다. 그래서 문서 높이를 코드 영역(정확·사전 계산 가능)과 동적 블록 영역(추정·측정·캐시)으로 분리하는 두 가지 기하 모델을 도입했고, 블록마다 변경을 일으킬 수 있는 상태(내용, 확장 여부, 측정 당시 폭 등)를 지문(fingerprint)으로 보관해 재측정·캐시 규칙을 정했습니다.
측정 스케줄러와 파이프라인 설계도 핵심입니다. 블록별 ResizeObserver를 바로 레이아웃에 쓰는 초기 설계는 피드백 루프와 비용 폭증을 야기해, 대신 스크롤이 정착했을 때만 동작하고 뷰포트 인근(약 2400px 범위) 후보만 일괄 읽는 단일 비동기 측정 패스를 적용했습니다. 화면에 마운트된 블록은 배치 내에서 한 번에 읽어 실제 높이를 기록하고, 오프스크린 보정은 제한적으로만 수행합니다. 동기적 보정은 사용자가 직접 일으킨 변화(예: 확장, 즉시 열리는 리플라이 등)에 한해 프레임 내에 허용하되 한 프레임당 1회로 제한합니다. 스크롤 점프를 막기 위해 식별자를 기준으로 앵커를 캡처·보정하는 방식도 도입했고, 데이터 파이프라인은 구조 우선 스트리밍, 필요 시점까지 작업 지연, 일부 최근 diff 캐시 유지로 UI 반응성을 보조합니다. 마지막으로 문제 재현과 회귀 방지를 위해 앱 자체의 구조화된 계측을 바탕으로 무인 probe·자동화 루프를 돌려 병목을 찾아내고 CI 테스트로 고정하는 접근을 썼습니다. 이 조합으로 백만 행급의 풀 리퀘스트도 실제로 열고 스크롤하며 댓글이 온전하게 렌더되는 경험을 목표로 했다는 점이 기술적으로 의미가 큽니다.
