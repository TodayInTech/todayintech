# GitHub availability report: September 2026

> GitHub Blog · 2026-10-14 · Company news

---

9월 GitHub 가용성 보고는 중앙 미동부(Central US)로의 서비스·데이터베이스 마이그레이션과 운영적 완화 조치의 진척을 수치로 보여주면서도 작업이 완료되지 않았음을 솔직히 밝힙니다. 160개 생산 서비스 중 120개가 Central US에 배포되었고, 51개 주요 MySQL 중 13개가 이전을 마쳤습니다. Azure가 코어 애플리케이션 읽기 트래픽의 65.4%, Git 읽기 48.3%, 스트림 처리의 80.2%를 처리하는 등 클라우드 이전 효과가 가시화되는 한편, 9월 11일 가용성 존 간 용량 불균형으로 배포·트래픽 증량이 일시 중단되었고 9월 30일의 공격적 목표는 달성되지 못했습니다. 공유 데이터베이스 부담 경감도 병행되어 인증 관련 테이블 이동으로 약 초당 100만 쿼리가 레플리카에서 제거되었고, 이슈·풀리퀘스트를 지탱하는 DB에서 약 9.8억개의 불필요한 편집 이력 행을 삭제해 약 1.8TB의 복구 가능 저장소를 확보했고, 주간 교착 상태는 6월 정점 대비 약 77% 감소했습니다.
보고서는 두 건의 의미 있는 장애 사례를 기술적 원인과 대응, 향후 완화책과 연결해 제시합니다. 9월 13일 사고는 백그라운드 정리 작업이 레플리카 지연만 감지하던 안전장치를 우회해 마스터에 부하를 쌓았고, 타임아웃 부재와 재시도 루프가 연결 소진을 초래해 1시간 28분간 영향을 줬습니다. 대응으로 내부 부하 축소, 잡 중단과 함께 데이터베이스 용량 기반의 추가 안전장치, 불필요한 재시도 차단, 서비스 시작 동작 개선 등이 계획되었습니다. 9월 28일에는 Copilot 코드리뷰 서비스 변경이 일부 고객에 대해 제한된(리뷰 코멘트 제외) 결과만 전송하면서 52분간 리뷰 미완료 상태가 발생했고, 모니터링·배포 절차 강화와 자동 회복·조기 통지 기능을 도입하여 재발률을 낮추려 합니다. GitHub Actions 측면에서는 Redis 연산 약 28% 감소와 상대적 CPU 30% 절감, 인프라 캐시로 Redis 대역폭 84% 감소·평균 응답시간 66% 감소 등 운영 여유(headroom)를 확보한 점도 기술적으로 의미가 큽니다. 전반적으로 보고서는 '가용성→용량→기능' 우선 원칙을 재확인하며, 수치 기반 개선과 여전히 남아 있는 구조적 리스크를 함께 제시해 엔지니어링 의사결정과 우선순위 설정에 실질적 단서를 제공합니다.
