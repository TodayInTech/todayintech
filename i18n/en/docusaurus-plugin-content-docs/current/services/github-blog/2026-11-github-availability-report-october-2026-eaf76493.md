# GitHub availability report: October 2026

> GitHub Blog · 2026-11-13 · 가용성 리포트

---

GitHub는 2026년 10월 가용성 리포트를 통해 **대규모 Azure 중앙미주(Central US) 이전과 컴퓨트 확장**을 진행했지만, 여러 운영·네트워크·인증 문제로 인해 월간에 걸쳐 8건의 성능 저하 인시던트가 발생했다고 공개했다. 보고서에는 이전 정도와 인시던트별 원인·대응·후속 개선이 일목요연하게 정리되어 있다.

## 중앙미주 이전과 용량 확장
GitHub는 11월 9일 기준으로 151개 프로덕션 서비스 중 **140개**, MySQL 프라이머리 50개 중 **32개**를 Azure Central US로 옮겼다. 중앙미주는 마이그레이션된 서비스 읽기 트래픽의 **63%**, 모놀리스 읽기 트래픽의 **66%**, Git 읽기의 **52%**를 처리한다. 또한 중앙미주 9개 Kubernetes 클러스터에 걸친 컴퓨트 확장으로 **용량을 두 배 이상** 늘렸고, 마이그레이션 서비스 트래픽은 3월 이후 **82% 증가**해 기존 데이터센터가 감당하던 주간 평균 부하를 초과하는 성장분을 중앙미주가 흡수하고 있다.

## 주요 인시던트와 직접 원인(선택된 사례)
- 10월 5일(약 3시간 45분): GitHub-hosted Actions의 잡 할당 서비스가 클라우드 제공자 측 일부 네트워크 장애로 DB 호출이 타임아웃까지 대기해 OOM으로 재시작, 다른 지역으로 트래픽이 몰리며 대기 및 실패가 확산됐다. 대응으로 데이터베이스·스토리지 페일오버와 용량 추가, 러너 할당 우선순위·복구 시간 단축 조치가 계획됐다. (chunk-0001)
- 10월 6일(약 3시간 43분): GitHub Enterprise Importer의 대량 쿼리 폭주가 공유 DB의 연결을 모두 소모해 github.com의 실패/지연을 초래. 마이그레이션을 일시 중단하고 쿼리를 소규모 배치로 바꾸는 완화책을 배포함. (chunk-0002)
- 10월 7일(총 약 19분): 데이터베이스 라우팅을 관리하는 새 머신이 오래된 레코드를 포함한 상태로 리더로 선출되어 쓰기 트래픽을 은퇴된 서버로 보냈다. 자동 검증을 통과한 잘못된 설정이 즉시 적용되며 쓰기 장애 발생. 재발 방지를 위해 서버 은퇴 절차·신규 라우터 추가 제어·설정 검증을 강화했다. (chunk-0002)
- 10월 19~21일: Actions 로그·캐시 연결 재시도가 특정 클라우드 리전 간 공유 네트워크를 포화시키거나 이벤트 스트리밍 플랫폼에서 재연결 폭주로 메모리·파티션 부하가 확대돼 webhook·감사로그 지연을 유발. 재연결 지연 추가, 메모리 알람 조기 경보, 핫 파티션 분할·이동 등의 대응을 시행했다. (chunk-0002, chunk-0003)
- 10월 28일(약 1시간 32분): Copilot의 일부 GPT 계열 모델 호출이 상류 모델 제공자와의 인증 자격증명(credential) 만료로 거부돼 약 10% 수준의 실패율 발생. 새 자격증명 배포와 인증 실패에 대한 재시도·모니터링 강화를 적용. (chunk-0003)
- 10월 30일(약 9분): 다수 서비스가 공유하는 데이터베이스 연결 풀 한계 도달으로 병합·SSH Git 작업 등이 실패. 문제 원인은 업데이트 흐름에서 조회가 쓰기 전후에 실행돼 연결을 불필요하게 장시간 점유한 패턴이었다; 이제 느린 조회를 쓰기 전에 수행하도록 순서를 바꾸고 연결 보유 시간 제한을 평가 중이다. (chunk-0003)

## 운영 개선과 남은 과제
보고서는 NAT 게이트웨이 완화로 사용량을 **85% 감소**시킨 사례, 특정 Actions 엔드포인트의 데이터베이스 읽기 피크를 **85% 감소**시킨 조치, 검색 토픽에 최소 3자 요구로 느린 쿼리를 약 **98%** 줄인 사례 등 구체적 개선을 제시한다. 동시에 GitHub는 '가용성→용량→기능' 우선 원칙을 재확인했고, **East US 3** 빌드아웃이 계획보다 약 1주일 지연되어 12월 첫 주에 첫 검증 트래픽 램프를 시작할 예정이라고 밝혔다. (chunk-0001)

## 기술 독자에 주는 시사점
이 보고서는 단순한 용량 이전이 아니라 용량 확대와 함께 운영 안전성(라우팅 검증, 자격증명 관리), 의존성 격리(데이터베이스·캐시·네트워크), 재시도·재연결 행동의 제어가 병행되어야 한다는 점을 실증적 사례로 보여준다. GitHub가 공개한 수치(마이그레이션 트래픽 증가율, 중앙미주가 담당하는 읽기 비중, 클러스터 확장 배수)와 인시던트 원인은 기술팀이 비슷한 이전·확장 작업을 설계할 때 우선 검토해야 할 구체 항목(라우팅 설정 검증, 장기 연결 보유 제한, 인증 자격증명 로테이션·모니터링, 재연결 랜덤화 등)을 직접 제시한다.

근거는 GitHub의 2026년 10월 가용성 보고서 문서(게시물 본문)에 한정해 설명했습니다.
