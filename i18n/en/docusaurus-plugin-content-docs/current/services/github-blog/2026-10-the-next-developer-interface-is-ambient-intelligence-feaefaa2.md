# The next developer interface is ambient intelligence

> GitHub Blog · 2026-10-15 · Company news

---

전통적으로 개발자는 키보드·마우스·에디터·터미널의 조합으로 작업을 해왔다. 그러나 글은 AI 에이전트가 저장소 문맥을 이해하고 적합한 모델을 선택해 파일을 편집하고 테스트를 실행해 PR을 생성하는 등 작업을 실행 가능한 '의도'로 바꾼다고 진단한다. GitHub Copilot의 에이전트 모드는 이 루프를 대화형으로 유지하면서 개발자가 결과에 대한 주도권은 그대로 갖되, 도구 사이를 헤매는 시간이 줄고 방향 설정·컨텍스트 제공·제약 정의·증거 검토 같은 상위 판단에 더 집중할 수 있게 한다는 것이 핵심 주장이다. 저자는 인터페이스를 세 계층—의도(모달리티), 실행을 계획·행동하는 하니스, 검사·재지정·승인을 담당하는 제어 평면—으로 나누어 설명하며, 최종 사용자는 이들 요소가 통합되면서도 제어를 잃지 않는 제품이 최적이라고 본다.
물리적 컨트롤의 재등장도 중요한 관점으로 다뤄진다. Logitech MX Keypad와의 협업 사례를 통해 반복적인 중단을 단축하는 하드웨어 단축키가 에이전트 기반 워크플로에서 어떻게 '흐름 유지'를 돕는지 보여준다: 파라미터화된 프롬프트 전송, 에이전트 세션 재개, IDE 명령 호출, 다단계 시퀀스 트리거 등이 가능하다. 동시에 글은 엔지니어링 관점의 열린 질문들도 제시한다—에이전트가 어느 수준의 저장소·조직 문맥을 유지할지, 자동화 가능한 툴 호출 범위, 자격증명·네트워크·시크릿의 범위 설정, 변경에 첨부될 증거의 형태, 다수 에이전트 간 조정 방식 등이다. 결론적으로 저자는 개발자를 배제하려는 것이 아닌 마찰을 제거해 판단과 통제에 더 집중하게 하는 방향이 '주변(ambient) 지능'의 목표라고 정리한다.
