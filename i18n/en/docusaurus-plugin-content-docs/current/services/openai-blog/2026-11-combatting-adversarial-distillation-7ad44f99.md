# Combatting adversarial distillation

> OpenAI Blog · 2026-11-20 · AI 보안/안전

---

OpenAI는 적대적 증류(adversarial distillation)로부터 모델의 '보호 추론'(chain-of-thought) 유출을 막기 위해 GPT‑6.2 계열에 걸친 다층적 방어를 공개했다. 공개 문서에 따르면 이 회사는 모델 훈련, 적대적 학습(adversarial training), 입력·출력 분류기, API 경계 설정, 캠페인 수준의 조사·집행을 조합해 대응하고 있다. (근거: OpenAI 블로그)

## 보호 추론 노출 억제의 핵심 성과
OpenAI는 내부 적응형 평가(adaptive black-box red-teaming)에서 GPT‑6 Astra의 기존 보호 장치에 비해 GPT‑6.2 Astra에서 보호 추론 회수 공격 성공률을 **54.0%에서 0.2%로** 대폭 감소시켰다고 밝혔다. 같은 평가에서 GPT‑6.2 Astra는 각 공격 유형별 평균 성공률이 **1% 미만**이었다. 이 수치는 보호 추론(teacher 모델의 내부 단계)을 학습 데이터로 활용할 때 발생하는 능력 이전 위험을 실험적으로 줄였음을 의미한다. (근거: chunk-0001, chunk-0002)

## 구현된 기술적 조치들
- 대입학습과 적대적 학습: 모델에게 추론 추출 시도를 인식하고 거부하도록 학습시키며, 정상적인 설명·지원 요청에는 응답을 유지하도록 설계했다. (근거: chunk-0001)
- 입력·출력 분류기: 요청을 분석해 추론 추출 시도를 판별하고, 어시스턴트 메시지와 도구 호출 인자에서의 누출을 탐지·차단한다. 특히 도구 호출 인자로 보호 추론이 노출될 수 있음을 명시적으로 다루고 있다. (근거: chunk-0001)
- API 경계·대화 연관성 고정: GPT‑6.2 Astra·Sol은 보호 추론을 해당 대화 기록에 묶어 관리한다. 대화 메시지가 수정되면 그 이후 생성된 추론은 API에서 제거되며, 이전(약한) 모델 가족이 GPT‑6.2의 보호 추론을 읽지 못하도록 차단한다. 이로써 대화 간 또는 모델 간 유출 경로를 줄였다. (근거: chunk-0002)
- 캠페인 수준 조사·집행: 대규모·조직적 추출 시도가 탐지되면 관련 계정 네트워크를 조사·제재하고, 조사 결과는 방어 강화에 사용된다. 올해 수천~수만 계정 규모의 주간 집행 사례가 보고되었다. (근거: chunk-0002)

## 업계·정책 연계와 정보공유
OpenAI는 다른 제공자 및 정부와의 협력을 강조한다. 특정 캠페인 분석 결과는 적절한 채널을 통해 공유해 관련 서비스의 남은 남용을 조사하도록 돕고, 일관된 기준(consistent-standards policy)과 공동 집행을 통해 전반적 방어 수준을 끌어올리려 한다. 의회 브리핑, 특정 행위자(DeepSeek, Moonshot AI/Kimi)에 대한 보고 등 대외적 조치도 언급됐다. (근거: chunk-0002, chunk-0003)

## 실무적 의미
이 조치들은 보호 추론을 포함한 내부 상태 정보가 불특정 다수의 학생 모델로 이전되는 경로를 줄여, 악의적 용도로의 능력 확산 위험을 낮춘다. 실무적으로는 다음과 같은 영향이 예상된다: distillation 공격의 비용과 탐지·차단 시점까지의 시간이 늘어나고, 모델 배포자는 요청·출력 로깅과 도구 인자 검사, 대화-연결성 관리 같은 기술·운영적 통제를 도입해야 한다는 점이 강조된다. 다만 OpenAI 자신도 일부 개선을 GPT‑6 Astra에 역적용 중이라고 밝혀 향후 적용 범위가 넓어질 전망이다. (근거: chunk-0001, chunk-0002)

출처와 수치(예: **54.0%→0.2%**)는 OpenAI의 공개 문서에 근거하며, 제시된 평가는 내부 적응형 테스트와 생산 환경과 유사한 설정을 반영한 결과라고 회사는 설명하고 있다. (근거: chunk-0001, chunk-0002)
