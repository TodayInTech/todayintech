# How iFood scales coding agents across 15,000 repositories

> OpenAI Blog · 2026-11-24 · 엔터프라이즈 AI 플랫폼

---

iFood는 개발팀들이 반복적·대량의 엔지니어링 작업을 직접 실행하지 않고 API로 위임하도록 설계한 내부 플랫폼, Remote Agents Platform을 도입해 **15,000개**에 달하는 코드 저장소 전반에 자동화 작업을 확장했다. 플랫폼은 사용자 호출을 REST API로 받아 격리된 원격 샌드박스에서 작업을 실행하고, 결과를 병합요청(MR) 형태로 되돌려준다.

## 에이전트 실행과 결정적(pre/post) 단계의 분리

플랫폼의 워크플로는 시작과 끝을 담당하는 **결정적 단계**(저장소 클론, 스킬 임포트, 작업 브랜치 설정 → MR 게시·아티팩트 공개)와, 그 사이에서 실행되는 **에이전트적 단계**(샌드박스 내부에서 GPT‑5.6 Luna가 수행하는 코드 변경·분석)를 조합한다. 이 설계는 반복 가능한 파일·브랜치 조작과 모델이 필요한 복잡한 결정 작업을 명확히 분리해 전체 흐름의 예측 가능성을 높인다.

## 샌드박스·툴체인·외부 통합

샌드박스는 Ubuntu 기반으로 Python, Java, Kotlin, C#, TypeScript, Rust, JavaScript, Go 등 iFood 생태계의 툴체인을 포함한다. 에이전트는 샌드박스 외부에서 Nexus, GitLab, Docker, Snyk, Kubernetes, AWS 같은 인프라와 연동해 실제 배포·의존성 검사·레지스트리 접근을 수행할 수 있다. 모든 실행은 격리되어 각 실행간 간섭을 줄인다.

## 모델 선택과 비용 고려

iFood는 모델을 선택할 때 단순 성능뿐 아니라 **지능, 효율성, 실행 속도**를 함께 비교해 GPT‑5.6 Luna를 채택했다고 밝혔다. 플랫폼은 지금까지 **25,000+** 실행을 완료하며 **총 270억 토큰**을 소비했고, 실행당 평균 비용은 **US$0.04**다. 이 수치는 대규모 자동화에서 단회 비용이 아니라 아키텍처적 제약으로 작용함을 조직이 직접 지적했다.

## 출력 검증: Structured Outputs의 도입

에이전트가 목표를 달성했는지 자동으로 판단하기 위해 iFood는 OpenAI의 Structured Outputs를 채택해 결과가 미리 정의한 계약(contract)을 따르도록 강제한다. 이 방식으로 성공/실패를 기계적으로 분류하고, 실패 시 오류를 표준 형식으로 회수해 후속 처리 흐름으로 연결할 수 있다.

## 실무 영향—보안 플랫폼 사례

이 플랫폼은 내부 보안 제품에 적용되어 취약한 의존성을 스캔하고 자동으로 수정하는 데 활용됐다. 마이그레이션 이후 취약점 수정의 **정확도와 해결 건수가 모두 두 배 이상** 증가했다고 iFood는 보고했다. 또한 비동기 실행(작업을 제출하고 결과를 나중에 확인)은 개발자가 장시간 모니터링에 묶이지 않으면서 루틴 작업을 위임할 수 있게 해 생산성 측면의 실질적 이득을 제공한다.

## 실무적 시사점(분석)

사실관계(플랫폼 구성, 수치, 모델, Structured Outputs 채택)는 공개 근거에 기반한다. 이 사례가 주는 교훈은 다음과 같다: 대규모 코드베이스에서는 '무엇을 자동화할지'보다 '어디에서 실행할지(런타임)'가 병목이 되는 경우가 많고, 비용과 출력 검증이 자동화의 지속가능성을 결정하는 핵심 요소다. iFood는 이를 내부 API·샌드박스·명세화된 출력으로 해결했고, 보안 팀처럼 고빈도·명확한 페인포인트에서 첫 적용을 통해 효과를 증명했다.

근거 문서에 기술된 구현 세부(예: 내부 스케줄러, 샌드박스의 네트워크 제어 정책 등)는 공개되지 않았다. 다만 제시된 숫자와 설계 원칙은 대규모 엔터프라이즈 환경에서 에이전트형 자동화를 도입할 때 직접 참고할 만한 실무적 지침을 제공한다.
